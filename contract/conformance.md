# Conformance checklist

Every implementation of goto-sms (any language) must satisfy these 23 behaviours. Each row gives the
requirement as written in the design spec and the Node tests that prove it. Test names are
searchable in `packages/node/test/`; a port should carry one test per row. The Node tests run against
an in-process fake GoTo (`packages/node/test/helpers/fake-goto.ts`), never the real service.

| #   | Requirement                                                                                                   | Node test(s)                                                                                                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | No `scope`/`prompt` in the authorize URL.                                                                     | `C1 authorize URL has client_id, redirect_uri, response_type=code, state and no scope/prompt`                                                                                                                          |
| C2  | The token call uses Basic auth with a form body.                                                              | `C2 token call uses Basic auth and form body without client_secret`                                                                                                                                                    |
| C3  | Connect is a POST; `state` is single-use, has a TTL, and is compared in constant time.                        | `C3 state is single-use and expires after 10 min`; `C3 two pending states both work`; `C3 startConnect sweeps expired states`                                                                                          |
| C4  | Refresh is single-flight, and a rotated refresh token is saved while an absent one keeps the old.             | `C4 single-flight: 5 concurrent calls on an expired token → one refresh`; `C4 rotation: rotated refresh token is stored; non-rotated one is kept`                                                                      |
| C5  | Refresh 400/401/403 means `login_expired`; 408/429/5xx and timeouts are temporary.                            | `C5 refresh ${status} → LoginExpiredError and login_expired flag; later calls fail fast`; `C5 refresh 503 → TemporaryError, no flag, tokens untouched`; `C5 refresh hang → TemporaryError after timeout, no flag`      |
| C6  | Accounts come from the Users/me SCIM getgo extension.                                                         | `C6 accounts from urn:scim:schemas:extension:getgo:1.0.accounts[] (value→key, display→name)`; `C6 a missing extension gives []`                                                                                        |
| C7  | Numbers are paged with `pageMarker` and de-duplicated.                                                        | `C7 numbers follow pageMarker across 3 pages and dedupe by number`                                                                                                                                                     |
| C8  | Phone numbers are normalized to E.164 with NANP validation; invalid input never reaches the network.          | `NANP loose formats`; `NANP rules: area/exchange start 2-9, no N11 area`; `junk is null`; `invalid number → invalid_number with no network call`                                                                       |
| C9  | Sending to the owner number is refused.                                                                       | `C9 owner number refused (no network)`                                                                                                                                                                                 |
| C10 | An opted-out number is refused before the network.                                                            | `C10 opted-out refused (no network)`                                                                                                                                                                                   |
| C11 | `dedupeKey` prevents a second send.                                                                           | `C11 same dedupeKey sends once, sequentially and concurrently`; `C11 a dedupeKey locked by another process is refused as retryable`                                                                                    |
| C12 | A timeout after send returns `uncertain`, with no retry.                                                      | `C12 hangNext → uncertain, fake saw exactly 1 POST`                                                                                                                                                                    |
| C13 | A 401 on send forces one refresh and one retry.                                                               | `C13 401 then success → sent after one refresh`; `C13 401 after the refresh too → not_connected, login expired`                                                                                                        |
| C14 | 403 and 10DLC errors are translated to readable reasons.                                                      | `C14 403 and 10DLC reasons`                                                                                                                                                                                            |
| C15 | "Sent" is never reported when the package isn't configured; log-only mode refuses production.                 | `C15 unconfigured → not_connected, fake saw 0 POSTs; logOnly + NODE_ENV=production throws at construction`                                                                                                             |
| C16 | The webhook checks the path secret in constant time, answers 204 first, and parses the envelope loosely.      | `C16 parse: party-invites envelope → message`; `C16 parse: id falls back to a stable sha256 of from\|to\|text\|timestamp`; `C16 parse: non-INBOUND_MESSAGE type, outbound direction, and garbage → null, never throws` |
| C17 | The channel needs `channelType`, and an existing channel is reused.                                           | `C17 creates channel with channelType Webhook when none matches; reuses a matching one`                                                                                                                                |
| C18 | The subscription carries `accountKey` in the query and the body, and falls back from ACCOUNT to ORGANIZATION. | `C18 subscription POST has accountKey in query and body; existing matching subscription → no POST`; `C18 on 4xx retries with ORGANIZATION`; `C18 a 403 on both shapes carries the GoTo body on GoToApiError`           |
| C19 | Polling dedupes, and compares timestamps with `Date.parse`.                                                   | `C19 polling dedupes across ticks`; `C19 mixed µs/ms timestamps ordered by Date.parse`                                                                                                                                 |
| C20 | STOP/START/HELP behave as described, with the single STOP confirmation allowed.                               | `C20 STOP adds opt-out, sends exactly one confirmation even though now opted out, emits with keyword`; `C20 START removes`; `C20 HELP replies with configured text`                                                    |
| C21 | Incoming texts are limited to 10/hour/number.                                                                 | `C21 11th text in an hour is logged and not emitted`                                                                                                                                                                   |
| C22 | Secrets never appear in API responses or logs, and are encrypted at rest.                                     | `C22 /api/status never contains clientSecret or tokens`; `seal/open round trip`; `tampered ciphertext throws DecryptError`                                                                                             |
| C23 | The setup page is unreachable without `authorize`.                                                            | `C23 router() without authorize throws; with authorize→false every /api route is 403; /callback and /inbound bypass authorize`                                                                                         |

The `/api/*` request and response shapes the setup page relies on are in [`http.md`](http.md).
